# reduce-over-engineering

Source: `/ponytail-audit` run over the whole repo (report delivered 2026-09-24, findings ranked).
Honest line accounting supersedes the audit's estimates where noted.

## Goal

Remove the over-engineering the audit found, without losing a single check.
Keep every observable behavior identical: same RPC contract, same fallback chain,
same credential records, same test counts and names.

## Non-goals

- No new dependency, no build step, no new abstraction.
- No public API change beyond one test-only export on the client bundle.
- No commit/push/PR: the user owns delivery.

## Decisions (and the audit items that were rejected)

| Audit item | Decision | Evidence |
| --- | --- | --- |
| #2 `markRemote` fallback descriptor | **Rejected** | `tests/remote-contract.test.mjs:177-183` asserts that path is discoverable via `remoteMethods()`. It is a tested compatibility path, not dead weight. |
| #6 `apiKeyToRecord` / `endpointToRecord` | **Rejected** | They encode the credential-record contract (`{kind:'api-key'}` / `{kind:'grant'}`) whose violation previously broke credential parsing (note at `src/host-core.js:478-484`). A trust-boundary contract is not bloat. |
| #8 reuse `clampNumResults` in `buildTavilyBody` | **Rejected (falsified)** | The audit called it semantically identical. `tests/host-core.test.mjs:175` asserts `limit: 0 → max_results: 1`; `clampNumResults` maps any non-positive/invalid value to its default 10, and also floors fractions. Not identical — behavior left untouched, with a comment recording why. |
| #9 `openspec/config.yaml` empty defaults | **Rejected** | Machine-generated by `sdd-init`, untracked local state, and any edit re-surfaces a pre-existing 179-char line in its generated context block. Not this feature's file. |
| #10 `buildQueryString` → `URLSearchParams` | **Rejected** | `src/host-core.js:161-166` documents that the dynamic-plugin sandbox has no `URL`/`URLSearchParams` globals. This module is shared with that sandbox; the constraint is recorded, not accidental. |
| #11 two patch files | **Rejected** | `patch.web.yml` (relative `./src/index.js`) and `cordis.patch.yml` (package name) anchor differently by design; cutting one removes a documented workflow, not complexity. |

## Tasks

- [x] **T1 — One copy of the interaction logic, tested where it ships.**
      `src/interaction.js` is deleted. `src/client/bundle.js` is now the single copy and
      adopts the tested contract it had drifted from: 12-bullet `MASK`, and `deriveView`
      returning `statusText` / `opacity` (the component consumes them instead of
      recomputing `statusText` inline and hardcoding opacity in two places). The bundle
      exposes `__internals` because the browser half cannot `require` local files; the
      37 assertions in `tests/interaction.test.mjs` now load the shipped bundle through
      the module-loader stub and pin exactly those functions. Behavior of the settings
      page is unchanged — the bundle now matches the contract its tests always asserted.
- [x] **T2 — The type gate stops being dead config.**
      Added `"typecheck": "tsc -p tsconfig.types.json"`, wired it into
      `prepublishOnly`, and documented it in both READMEs. `typescript@7.0.2` +
      `tsconfig.types.json` now have a caller.
- [x] **T3 — `src/index.js` shrinks.** `resolveCandidates()` returns the provider id
      list directly (no `{id}` wrapper objects), the `failures[]` array became a
      `lastError` string (only its last element was ever read), and the
      `apiKeyAvailable` / `endpointAvailable` one-line wrappers are inlined.
- [~] **T4 — reverted.** See the #8 row above; the test suite proved the audit's
      equivalence claim wrong, so `buildTavilyBody` keeps its own clamp plus a comment.
- [x] **T5 — Verification.** All three gates green (below), and the only files touched
      are the ones the tasks name.

on a green test. The `__internals` export is an extra key on the bundle's `module.exports`;
the smoke test proves the factory still loads and exports `name` / `inject` / `apply`, but
the real harness loader was not available to run.
