## Deviations from the design

1. **Peer-use evidence has a third, documented channel.** D8's dead-peer rule reads "named by an
   import in `src/`+`tests/` **or** by `dsh.client.inject`". `@deepseek-ai/dsh-web` is a
   parent-confirmed peer that is imported nowhere (explore.md records it is reached through
   `ctx.get('web')`, now `src/index.js:413`), so the literal reading would have flagged it, and no
   allowed edit surface could ever make task 6 green. The checker therefore accepts a third
   evidence channel — the capability seam the peer provides, reached as `ctx.get('<seam>')` — and
   `tests/manifest.test.mjs` documents it in `peerUseEvidence`. The rule stays non-vacuous:
   `@deepseek-ai/dsh-tools` has no import, no `inject` entry and no seam, so it is still reported
   (proven by the pre-change-literal control and by mutation M5), and the reverse direction
   (`inject` names something that is not a declared peer) is reported as `inject-not-a-peer:`.
2. **`remotes.register` takes one argument in the installed API.** D2's illustrative snippet shows
   `host.remotes.register(ctxOf(), probe(...))`; the shipped `Registry.remotes` getter is
   `RemoteStore.view(ctx)`, whose `register(contribution)` closes over the ctx. The tests call
   `remotes.register(probe(...))` on both faces — the same public validation path D2 selected
   (`lib/index.js:563-577`, `lib/client.js:1354-1358`), reached through the reachable API.
3. **`docs/DESIGN.md` §6 counts updated too.** D7's table does not list §6, but the new manifest
   suite made "134 pure / 12 environment" false in a file this change edits; leaving it would have
   been a knowingly stale claim. Counts now match the actual runs (140 / 19).
4. **Task 7's "single-`inject` assertion made explicit"** is realised as an explicit
   `exported.inject === ['slots', 'remote', 'locale']` assertion plus the `$mount`-disposer
   assertion; the "exactly one `slots.inject` call" count assertion already existed from task 5.
5. **Stub-ctx assumption from D2 confirmed by execution, and `ctx.effect` needed one refinement in
   the smoke suite.** The D2 `ctxOf()` stub (`reflect.provide` capture + `logger.warn` +
   `effect`) is sufficient for both faces. In `tests/client-bundle.smoke.mjs`, `ctx.effect` now
   *invokes* its callback (instead of ignoring it) so the `locale.register` dictionaries and the
   `$mount` disposer are observable; that is a stub-only change, no production behaviour affected.
6. **D1's accepted lockfile cost is smaller than forecast** (~367 generated lines in task 1, then a
   net-reducing rewrite after the peer/dev bump in task 6); `@deepseek-ai/dsh-tools` left the tree.
